## Применение Skill: аудит

Использован **web-design-guidelines**. Правила получены через GitHub connector (эквивалент чтения WebFetch, указанного в инструкции). Проверка выполнена статически по исходному HTML, CSS и JS; строки ниже относятся к исходному `index.html`, до декодирования srcdoc.

### index.html

- `index.html:122` — высокий приоритет: подписи полей пожара не связаны с input/select через for/id или вложение. Подтверждено 24 из 24 полей. Добавить связь, сохранив существующие id.
- `index.html:329` — высокий приоритет: 24 из 32 полей металла без связанных подписей; 8 чекбоксов имеют корректный label[for].
- `index.html:612` — высокий приоритет: 27 из 27 полей фасада без связанных подписей.
- `index.html:620` — подписи трёх опций фасада не переключают чекбоксы. Связать label с reinfOn, hydroOn и jointOn.
- `index.html:692` — высокий приоритет: delCalc сразу удаляет сохранённый расчёт; нет подтверждения или возможности отменить.
- `index.html:696` — удаление реализовано ссылкой href="#"; для действия нужен button с понятным названием конкретного расчёта.
- `index.html:135` — результат и предупреждение пожара меняются без live-region; аналогично металл на строках 438/454/458 и фасад на 627. Добавить отдельный краткий статус aria-live="polite", не озвучивать весь длинный клиентский текст при каждом вводе.
- `index.html:77` — выбранный калькулятор отмечен только CSS-классом; состояние не передаётся вспомогательным технологиям. Использовать aria-pressed для кнопок либо полноценный паттерн вкладок с клавиатурным управлением.
- `index.html:707` — выбор вкладки не отражается в URL: нельзя поделиться ссылкой на металл/фасад, перезагрузка возвращает пожар.
- `index.html:121` — переход h1 → h3 нарушает иерархию заголовков; аналогично металл на 328 и фасад на 611.
- `index.html:83` — нет ссылки пропуска шапки к основному содержимому; внутри документов калькуляторов также нет main/skip-link.
- `index.html:122` — у полей отсутствуют name и осмысленная политика autocomplete; проблема повторяется во всех трёх формах.
- `index.html:142` — min у числовых полей не сопровождается проверкой validity и сообщением рядом с полем: ручной ввод отрицательных значений поступает в расчёт. Аналогично фасад на 634. Правила допустимых значений следует согласовать, сохранив бизнес-формулы.
- `index.html:306` — клиентский текст сохраняет пробелы, но не имеет overflow-wrap для длинных адресов/комментариев; проверить на узком экране. Аналогичные стили на 111 и 601.
- `index.html:36` — для кнопок нет явного hover-состояния; аналогично кнопки внутри iframe на 110, 295 и 600.
- `index.html:107` — для числовых сравнений в таблицах не задан font-variant-numeric: tabular-nums; аналогично 283 и 597.

### showcase/index.html

- `showcase/index.html:122` — нет skip-link к основному содержимому.
- `showcase/index.html:125` — пустая сетка до завершения fetch, нет видимого статуса загрузки или aria-busy.
- `showcase/index.html:191` — техническая ошибка загрузки попадает в сообщение пользователю без понятного следующего действия; добавить предложение повторить загрузку.
- `showcase/index.html:119` — имя MultiCallculator не помечено translate="no".

### Что уже сделано хорошо

У iframe есть title, у страниц указан lang="ru"; масштабирование не запрещено. Основные действия используют native button. Для суммы используется toLocaleString("ru-RU"), сохранение фасада защищено try/catch. Ошибка витрины имеет role="alert". Анимаций и внешних шрифтов/изображений в проверенных файлах нет, поэтому соответствующие разделы правил неприменимы.

Стандартное браузерное выделение фокуса не отключено — отсутствие отдельного :focus-visible само по себе не заявлено как доказанная потеря фокуса. Реальный контраст, переполнение и положение фокуса требуют браузерной проверки. Англоязычные рекомендации Title Case и "&" не переносились механически в русский интерфейс.
